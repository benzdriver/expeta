# Expeta JSON Summary 改进任务列表

## 目标
解决当前系统生成的 JSON summary 过于空泛的问题，提升输出的具体性和实用性。

## 任务分解

### Phase 1: 提示词工程改进 (优先级: 🔴 高)

#### Task 1.1: 重构答案生成提示词
- **文件**: `reasoning/local_reasoning/answer_generators.py`
- **改进内容**:
  - 添加结构化输出模板
  - 要求具体的类名、方法名、技术栈
  - 禁止使用空泛词汇
  - 添加高质量示例
- **预计工时**: 4小时
- **验收标准**: 生成的答案包含具体的实现细节

#### Task 1.2: 优化问题生成策略
- **文件**: `reasoning/local_reasoning/question_generators.py`
- **改进内容**:
  - 按阶段设计问题模板
  - 确保问题引导具体回答
  - 添加追问机制
- **预计工时**: 3小时
- **验收标准**: 问题能够引出具体的技术方案

#### Task 1.3: 增强摘要更新逻辑
- **文件**: `reasoning/local_reasoning/summary_updaters.py`
- **改进内容**:
  - 使用严格的 JSON 模板
  - 添加字段验证
  - 实现增量更新策略
- **预计工时**: 4小时
- **验收标准**: 生成的 JSON 符合预定义结构

### Phase 2: 推理链架构重构 (优先级: 🔴 高)

#### Task 2.1: 重新设计推理轮次
- **文件**: `reasoning/local_reasoning/local_chain.py`
- **改进内容**:
  - 定义4个聚焦的推理阶段
  - 每个阶段有明确目标
  - 实现阶段间的信息传递
- **预计工时**: 6小时
- **验收标准**: 每轮推理产出明确的设计要素

#### Task 2.2: 优化推理配置
- **文件**: `reasoning/local_reasoning/round_config.py`
- **改进内容**:
  - 为每个阶段定义专门的配置
  - 添加质量检查点
  - 实现动态轮次调整
- **预计工时**: 3小时
- **验收标准**: 配置支持细粒度控制

### Phase 3: 上下文优化 (优先级: 🟡 中)

#### Task 3.1: 精准上下文构建
- **文件**: `knowledge/context_retrieval.py`
- **改进内容**:
  - 根据推理阶段构建相关上下文
  - 移除硬编码的示例
  - 实现动态相似度检索
- **预计工时**: 5小时
- **验收标准**: 上下文信息相关性提升

#### Task 3.2: 优化实体存储
- **文件**: `knowledge/entity_storage.py`
- **改进内容**:
  - 存储更结构化的实体信息
  - 添加实体类型标注
  - 支持领域特定模板
- **预计工时**: 4小时
- **验收标准**: 实体信息更加详细和结构化

### Phase 4: 质量控制系统 (优先级: 🔴 高)

#### Task 4.1: 实现质量评估器
- **文件**: `common/quality_validator.py` (新建)
- **改进内容**:
  - 检查输出具体性
  - 识别空泛词汇
  - 验证必需字段
  - 计算质量分数
- **预计工时**: 6小时
- **验收标准**: 能够准确评估输出质量

#### Task 4.2: 添加重试机制
- **文件**: `reasoning/local_reasoning/retry_handler.py` (新建)
- **改进内容**:
  - 基于质量分数的重试
  - 改进提示词的反馈循环
  - 最大重试次数限制
- **预计工时**: 4小时
- **验收标准**: 低质量输出能够被改进

### Phase 5: 领域知识注入 (优先级: 🟡 中)

#### Task 5.1: 创建模式库
- **文件**: `knowledge/pattern_library.py` (新建)
- **改进内容**:
  - 预定义常见模块的设计模式
  - 技术栈推荐
  - 最佳实践模板
- **预计工时**: 8小时
- **验收标准**: 支持10+种常见模块类型

#### Task 5.2: 实现智能模板选择
- **文件**: `reasoning/template_selector.py` (新建)
- **改进内容**:
  - 根据实体类型选择模板
  - 动态调整提示词
  - 注入领域特定知识
- **预计工时**: 5小时
- **验收标准**: 自动选择合适的设计模式

### Phase 6: 测试和验证 (优先级: 🔴 高)

#### Task 6.1: 单元测试套件
- **文件**: `tests/unit/test_quality_improvements.py` (新建)
- **测试内容**:
  - 质量评估器测试
  - 提示词模板测试
  - 重试机制测试
- **预计工时**: 6小时
- **验收标准**: 覆盖所有新功能

#### Task 6.2: 集成测试
- **文件**: `tests/integration/test_improved_generation.py` (新建)
- **测试内容**:
  - 端到端生成质量测试
  - 不同类型实体的测试
  - 性能基准测试
- **预计工时**: 5小时
- **验收标准**: 验证整体改进效果

## 实施顺序

1. **第一周**: Phase 1 + Task 4.1
2. **第二周**: Phase 2 + Task 4.2
3. **第三周**: Phase 3 + Phase 5
4. **第四周**: Phase 6 + 调优

## 成功指标

1. **具体性提升**: 90%的输出包含具体类名和方法名
2. **质量分数**: 平均质量分数 > 80/100
3. **空泛词汇减少**: 空泛词汇使用率 < 5%
4. **测试覆盖**: 新功能测试覆盖率 > 90%

## 风险和缓解措施

1. **风险**: LLM 可能不遵循严格模板
   - **缓解**: 使用 few-shot 示例和强制格式验证

2. **风险**: 过度约束导致创造性降低
   - **缓解**: 在框架内保留灵活性空间

3. **风险**: 性能下降due to质量检查
   - **缓解**: 异步处理和缓存优化

## 监控和评估

- 建立质量指标仪表板
- 定期评审生成的输出
- 收集用户反馈
- 持续优化提示词
