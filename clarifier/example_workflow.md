# Clarifier 工作流程示例

## 场景 1: 从零开始的交互式澄清

### Step 1: 初始对话
```
助手: 您好！我来帮您理清项目需求。能简单描述一下您想要构建什么吗？

用户: 我想做一个移民顾问管理系统，帮助顾问管理客户的申请流程。

助手: 理解了！为了更好地帮助您，我有几个问题：
1. 您的主要用户是移民顾问公司还是独立顾问？
2. 大概需要管理多少客户？
3. 最希望解决的痛点是什么？

用户: 主要是独立顾问和小型事务所，每个顾问大概管理50-200个客户。最大的痛点是文档管理混乱和申请进度难以追踪。
```

### Step 2: 深入澄清
```
助手: 明白了。关于文档管理和进度追踪，让我进一步了解：

对于文档管理：
- 需要管理哪些类型的文档？
- 文档需要客户上传还是顾问上传？
- 是否需要文档模板功能？

用户: 主要是申请表格、护照、学历证明等。需要双方都能上传，最好有模板功能，可以自动生成一些标准表格。

助手: 对于进度追踪：
- 需要追踪哪些关键节点？
- 客户是否需要看到进度？
- 是否需要自动提醒功能？

用户: 需要追踪递交、补料、面试、批准等节点。客户需要实时看到进度，最好有邮件和短信提醒。
```

### Step 3: 功能确认
```
助手: 基于我们的讨论，我总结了核心功能：

1. **客户管理**
   - 客户信息录入和管理
   - 客户分类（投资移民/技术移民/团聚移民）
   - 客户状态跟踪

2. **文档管理**
   - 双向文档上传（顾问/客户）
   - 文档分类和版本控制
   - 文档模板和自动生成

3. **进度追踪**
   - 可视化申请流程
   - 关键节点提醒
   - 客户端进度查看

4. **通知系统**
   - 邮件/短信自动提醒
   - 待办事项管理
   - 重要日期提醒

这些功能符合您的需求吗？还有什么需要补充的？

用户: 很好！再加一个费用管理功能，需要记录服务费用和官方费用。
```

## 场景 2: 基于现有 PRD 的分析优化

### Input: 现有的 PRD 文档
```markdown
# 移民服务平台需求文档

## 背景
很多人想要移民但不知道如何开始...

## 功能
- 用户注册登录
- 查看移民资讯
- 在线咨询
- 文档上传
...
```

### 系统分析过程:

#### Round 1: 理解项目
```
分析焦点: 项目核心价值和定位
- 识别目标用户群体
- 理解核心业务问题
- 提取关键业务目标
```

#### Round 2: 需求深化
```
分析焦点: 功能细化和优先级
- 将模糊需求具体化
- 识别隐含需求
- 确定功能优先级
```

#### Round 3: 补充缺失
```
分析焦点: 完整性检查
- 补充非功能需求
- 添加约束条件
- 识别潜在风险
```

#### Round 4: 结构化输出
```
生成统一格式的 JSON Summary
包含完整的需求细节和补充内容
```

### Output: 增强后的结构化需求

系统会生成：
1. **完整的 JSON Summary** - 结构化的需求数据
2. **增强版 PRD** - 补充了缺失内容的完整文档
3. **分析报告** - 显示哪些内容被补充或优化

---

## 优势总结

1. **适应性强**: 既支持零起步，也支持已有文档
2. **用户友好**: 使用业务语言而非技术术语
3. **透明可控**: 所有中间结果可见可改
4. **质量保证**: 多轮验证确保完整性
5. **易于集成**: 复用现有代码，降低开发成本
